* 2026-10-16 — verify.pl did not tie the stored legs to the visiting order
- *Found by:* an independent review by OpenAI Codex (2026-10-16); reproduced by Claude
  Code before the change.
- *The hole:* =verify.pl= checked that =visit/2= is a permutation of 1..34 and summed
  the stored legs =route_optimized/4=, but never checked that those legs connect
  consecutive visits. Reordering =visit/2= while keeping the legs still passed.
  (=check_certificate.pl= recomputed the length from the visits and was not fooled by
  this one; its own hole is logged in [[file:../certificate/CORRECTIONS.org][../certificate/CORRECTIONS.org]].)
- *Not affected:* the published tour and its length, 3,527 km.
- *What changed:* =verify.pl= now computes the length from consecutive visits via
  =dist/3=, and requires every stored leg to be exactly the leg between two
  consecutive visits, with the right distance. 22 → 38 lines. Its output on the
  published files is unchanged.
